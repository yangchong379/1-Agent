# 04 AI 辅助使用记录

## 本轮实际使用范围

使用 Codex 对话中的 AI 编程助手完成：需求拆解、Python 工程及规则/数据库/模型适配实现、合成数据生成、测试编写、CLI 与评估执行、Trace 整理和文档编写。AI 查阅了 OpenAI/DeepSeek 官方工具调用文档，修正接口参数兼容选择。未使用多Agent或接入真实发布平台。真实接口密钥由用户在本机输入，未写入仓库和运行记录；对话中误发的密钥已提示撤销，没有将其用于调用。

AI编程助手和项目运行时模型是不同角色：开发由AI辅助完成；`examples/runs/mock`明确使用MockModel，`examples/runs/live`与`live-retry-1`使用真实deepseek-flash。不能把开发过程中AI的推理或离线Mock当作项目运行时真实模型决策证明。

## 使用过的关键请求与产出

- 输入完整题目：生成满足目录规范的 CLI 工程和验收材料。
- 时段冲突/确认边界：实现不可由模型传入的确认状态；原始要求保留、替代时段待用户同意。
- 幂等和保存失败：采用 SQLite 唯一约束、事务内冲突检查、提交前故障注入与回滚。
- 模型接入：收到官方平台链接后按官方文档核对deepseek-flash对应V4.1 Flash；用户在本机输入密钥，真实运行记录与离线记录分开保留，不伪造或改写失败。
- 效果证明：执行自动化测试与离线场景，实际产物位于 [examples/runs/mock](../examples/runs/mock/REPORT.md)。

## 验证与修正

当前55个测试和13组离线场景全部通过。历史上从`required`统一改为`auto`以适配思考模式，随后真实评估发现仅靠提示不能保证恰好一次调用。此次改为非思考模式`required`、其它模式`auto`，再增加显式拒绝与有界纠正；读取/补查后重审的反馈也已澄清。用户完成五项真实重跑，5/5通过，首轮失败保留；另发现保存后重读的审核显示问题，AI修正成功保存时审核快照并用观察到的动作序列做离线回归，没有额外模型调用，也没有修改原始实测JSON。

所有测试输出、数据库快照与 Trace 为程序运行结果。没有手工把失败改写为成功；没有模型配置时保留“未验证”，没有 GitHub 地址时保留“未推送”。

真实模型后续记录：用户实际运行首轮13组评估和修复后五项重跑；AI逐项核查Trace和数据库快照，定位问题、修复代码、增加回归测试并整理对照报告。首轮8/13与重跑5/5分别记录，不编造成单轮13/13。用户负责本机密钥输入，AI未读取、保存或使用聊天中暴露的密钥，也未获取已关闭进程中的凭据。原始首轮数据和修复后重跑分目录保留。
