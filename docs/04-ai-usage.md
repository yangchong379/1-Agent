# 04 AI 辅助使用记录

## 本轮实际使用范围

使用 Codex 对话中的 AI 编程助手完成：需求拆解、Python 工程及规则/数据库/模型适配实现、合成数据生成、测试编写、CLI 与评估执行、Trace 整理和文档编写。AI 查阅了 OpenAI/DeepSeek 官方工具调用文档，修正接口参数兼容选择。未使用多 Agent，未接入真实发布平台，未读取用户隐私资料或真实密钥。

AI 编程助手和项目运行时模型是不同角色：本项目开发由 AI 辅助完成；当前提交的运行记录由明确标识的 `MockModel` 产生，不能把开发过程中 AI 的推理等同于项目运行时真实模型决策。

## 候选人与 AI 的贡献边界

| 参与方 | 本轮能够确认的贡献 |
|---|---|
| 用户/候选人 | 提供完整考核题目和规范；说明暂时没有 GitHub 仓库；说明有“DeepSeek 4.1”接口并询问接口配置概念；提供 DeepSeek 官方平台链接以核对接口配置 |
| AI 助手 | 设计并实现当前代码、文档、测试、评估材料；执行本机验证；整理待补事项 |
| 候选人独立代码修改/独立验证 | **本轮尚未提供记录**，不得表述为候选人已独立完成；实际操作后须按下方模板补记 |

没有候选人修改过代码或独立通过测试的证据，因此当前不编造个人贡献、学习经历或独立用时。提交前候选人须能够解释代码，并据实补充自己完成的工作。Git 提交作者的 AI 标识仅表示当前初稿由助手生成，不代表候选人身份。

## 使用过的关键请求与产出

- 输入完整题目：生成满足目录规范的 CLI 工程和验收材料。
- 时段冲突/确认边界：实现不可由模型传入的确认状态；原始要求保留、替代时段待用户同意。
- 幂等和保存失败：采用 SQLite 唯一约束、事务内冲突检查、提交前故障注入与回滚。
- 模型接入：保留用户指定模型信息，收到官方平台链接后按官方文档核对 `deepseek-flash` 对应 V4.1 Flash；密钥配置未完成，不伪造 live Trace。
- 效果证明：执行自动化测试与离线场景，实际产物位于 [examples/runs/mock](../examples/runs/mock/REPORT.md)。

## 验证与修正

实际执行39个测试和13组离线场景，全部通过；包括并发争抢、批准更新失败回滚、事务无法启动、模型响应结构异常和查询后发生新冲突。初版接口使用 `tool_choice=required`；阅读 DeepSeek 官方说明发现思考模式不支持该值，改为 `auto`，应用仍强制要求一次返回一个合法工具调用。该修正经过适配器单元测试，尚未远端实测。

所有测试输出、数据库快照与 Trace 为程序运行结果。没有手工把失败改写为成功；没有模型配置时保留“未验证”，没有 GitHub 地址时保留“未推送”。
